# AWS Cloud Security Implementation ☁️🔐
**Academic Project, ECPI University** | Cloud Security | AWS

## 📋 Overview
In this project, I implemented security monitoring and auditing in an AWS environment. I configured AWS-native security services for continuous visibility into account activity and threat detection, then wrote incident response procedures following AWS best practices.

## 🎯 Objectives
- Record and audit all account activity and API calls
- Detect suspicious or malicious behavior automatically
- Monitor the environment and alert on security events
- Document a clear process for responding to incidents

## 🛠️ Technologies
`AWS` `IAM` `AWS CloudTrail` `Amazon GuardDuty` `Amazon CloudWatch`

## 🔧 What I Implemented
| Service | Purpose | What I configured |
|---|---|---|
| **AWS CloudTrail** | Auditing | Logging of account activity and API calls for investigation and compliance |
| **Amazon GuardDuty** | Threat detection | Continuous monitoring for suspicious activity and security findings |
| **Amazon CloudWatch** | Monitoring & alerting | Metrics, logs, and alarms for real-time visibility into security events |
| **IAM** | Access control | User and permission management for the environment |

## 🚨 Incident Response Procedures
I wrote incident response procedures aligned with AWS best practices, covering:
1. **Detection:** identifying a threat through GuardDuty findings or CloudWatch alarms
2. **Investigation:** reviewing CloudTrail logs to trace what happened and who did it
3. **Containment:** limiting the impact (for example, restricting compromised credentials)
4. **Recovery:** restoring normal operations
5. **Lessons learned:** updating controls to prevent recurrence
